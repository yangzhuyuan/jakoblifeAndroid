## 补充证据（17:41 会话日志，errCode 已拿到）

决定性新证据：`17:41:36.795 回复ack数据重试失败, 0e000619030100000100, {"errMsg":"writeBLECharacteristicValue:fail property not support","errCode":10007}`（Main.vue:7693）。

- 失败路径不是运动命令（本次运动命令首发成功 23.603），而是**历史同步期间 ACK 队列写入**（flushBpw1AckQueue 重试路径 7693 行），同样特征值 BPW1write + writeNoResponse。
- 10007 "property not support" 是瞬时条件：同一会话同一特征值同一 writeType 四次成功（初始化/校时/运动/同步），仅在高频 notify 洪峰期（睡眠/心率历史包 34.367/34.816）失败两次 → 平台在设备推送洪峰期间瞬时拒绝 writeNoResponse 写入，映射为 10007。
- 时间线佐证时序竞争：校时写成功 12.542 → timeAck08（设备回 0e..08，CMD02，8287-8288 判定）5s 内未到 → 超时 → +2s+4s → 运动命令 23.603 发出，恰在设备 23.7s 开始推步数之前 → 首发成功。若 timeAck08 早到，运动会提前到 ~18.5s 落在推送窗口内 → 10007 → 2s 重试（即 16:36 会话现象）。两次会话差异 = 时序抖动。
- 影响：ACK 双失败后该 ACK 丢弃（7693-7698 继续 flush），设备可能重发；整体链路健康，可容忍。
- 规律：**设备高频推送时段写必失败（10007），安静时段写必成功**。根治仍须改代码（写前通道门控/notify 间隙择时/fail 打印 err）。
